## 2026-10-08 Primary buttons painted only 320 of 360pt (white strip on the right)

- **Symptom (Tu).** Every primary button (Lưu mật khẩu, Lưu mặc định, ...) showed the right colour but a white strip on its right edge.
- **Root cause (source + measurement).** `PrimaryCtaFill` rendered `<Svg width="100%" height="100%" style={absoluteFill}>`. react-native-svg 15.15.4 turns the `width`/`height` props into style overrides pushed after `style` (`Svg.tsx`, `overrideStyles.width = '100%'`), so Yoga sees a percentage width, which resolves against the parent content box. `KaelButton` has `paddingHorizontal: 20`; in the screenshot the fill is 320pt of a 360pt button = 360 - 2 x 20. The Auth button has no side padding, which is why the reference looked right.
- **Fix.** `PrimaryCtaFill` now wraps the Svg in an absolute-fill `View` (padding box, no padding of its own), the same pattern `MintAura` uses; the Svg inside keeps width/height 100%. One change covers every filled primary CTA (Auth, shared Kael, Worker stages, banner). Pillar `P322` gained a frame case; mutation (drop the frame's absolute fill) observed red.
- **Roles.** Customer, Worker and Admin all paint primary buttons through `KaelButton` / `PrimaryCtaFill` (no other mint paint exists: grep of `button.primary.gradient`), so the one fix covers them. The same defect class was then removed everywhere it existed: new `components/ui/fill-svg.tsx` (`FillSvg`, absolute-fill frame + Svg) now backs `PrimaryCtaFill` and the home hero / guidance banner, worker home blend root, stage-six connector, stage-two pill gradient and stage-ten hero gradient. `IncomeOrbWithdrawFill` was already safe (absolute Svg without width/height props). P322 gained a source scan: no `<Svg` with a percentage width and an absolute style; it was observed red on stage-ten before that file moved to `FillSvg`.
- **Verified.** mobile `tsc` 0, jest 261 suites / 2397 tests, comment-discipline, structure, pillar-registry clean. Not run on a device: the layout mechanism is read from react-native-svg source and matched to the measured 320/360 ratio; Yoga itself does not run in jest.

## 2026-10-08 Placeholder and typed text misaligned in Kael Chat composer, same class fixed in every input

- **Symptom (Tu).** In the Customer Kael Chat composer (iOS screenshot) the typed "Hi" sat lower than the camera and send icons; Tu asked for the root cause, the same check on every other placeholder + text, and a thorough fix.
- **Root cause (source-derived, React Native 0.86.2).** A TextInput style carrying `lineHeight` (the composer spread `typography.subheadline`, 15/20) builds a paragraph style with min/max line height for both placeholder and typed text, but only the typed attributed string passes through `RCTApplyBaselineOffset` (`RCTAttributedTextUtils.mm`: offset = (lineHeight - font.lineHeight) / 2, skipped when lineHeight is below the font's line). The placeholder uses `_defaultTextAttributes` (`RCTUITextView.mm`, `RCTUITextField.mm`), which have no offset, so the two draw at different heights. The old 12pt padding was tuned for the 20pt line, which hid it from the unit tests.
- **Fix.** `components/ui/input-text-style.ts` `withoutInputLineHeight(style)`; applied inside `KaelTextInput` and `KaelTextField` (covers every shared input, including the booking description/address), at the style source of both composers (so the ghost overlay Text, which reuses the style, matches), and on all 9 raw `<TextInput>` files (home search, session rename rows, worker home search, proposal form, stage 8 note, stage 5 note, RFQ panel, admin policy). Composer `paddingVertical` 12 -> 13 and booking description `paddingTop` 27.5 -> 27.25 re-centre the font's own line (~18pt / ~15.5pt) in the unchanged 44/70pt boxes.
- **Guard.** Pillar `P334-input-line-height` (helper, primitives, both composers, and a source scan that every `<TextInput` outside `kael-primitives.tsx` is paired with a `withoutInputLineHeight(`); mutation (helper returns the style untouched) observed red, 3 of 4 cases. Updated pins that asserted the old `lineHeight` in the customer chat, worker chat, home search and booking tests.
