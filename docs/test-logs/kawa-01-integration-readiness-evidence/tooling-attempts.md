# Tooling attempts and evidence boundaries

- The early REPL-spawned wrappers named sse-tracer-red, sse-tracer-red-valid and sse-red-runtime did not locate pnpm. One wrapper reported exit 0 despite the command-not-found error. These are invalid runner attempts, never PASS or a product reproduction. Their raw logs are retained. The authoritative first reproduction is sse-red-real.log.txt from exec_command: one failing assertion / fifteen passing controls, exit 1.
- ship:check emitted its complete ten-green-machine-gates / Git-state-failed summary and explicit child exit 1; the outer shell then lingered with only its conhost. Only that owned wrapper was interrupted; no app or unrelated process was stopped. Subsequent unrun gates resumed, and a complete final pass followed source stabilization.
- Baseline and simulation pnpm exec encountered ERR_PNPM_UNSAFE_TASK_RUN_STATE_PATH on the dependency junction. No pnpm guard was changed. Direct Node/ESLint and Node/Jest ran the actual configurations with those read-only shared modules. The baseline lint and integration test results quoted in the report come from those direct successful runner invocations, not the refused pnpm attempts.
- The initial baseline scanner/export attempts and all preliminary/final logs are distinguished by filenames and result records. Raw originals are kept outside the export in ignored scratch; personal path redactions and the two JSON test-title redactions are declared.
