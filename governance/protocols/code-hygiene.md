# Kael Protocol: `kael-core-hygiene`

Canonical procedure for the always-on `kael-core-hygiene` skill (`.claude/skills/kael-core-hygiene`, `.agents/skills/kael-core-hygiene`). `governance/skills.md` Core Skill 5 is a short pointer to this file; this file is the single source.

Apply this whenever you write, edit, or review code. It is not a task-class protocol you opt into — it runs on every code change, before you add any comment, header, or note.

## The standard

Write source the way a senior developer hands it to a reviewer: the code and its comments carry only what the next engineer needs to understand and safely change it. The file is not your worklog, your changelog, or a transcript of the conversation that produced it. Authorship lives in `git blame`; history lives in the commit message and `docs/`; the task lives in the PR. None of that belongs baked into the source.

Two failure modes this protocol kills:

- **AI residue** — dated/status/plan-tagged banners, "added by Claude/Codex", "as requested", first-person narration of what you just did.
- **Noise** — comments that restate the code, dead commented-out blocks, bare `TODO`s, editorializing, and apologetic or conversational tone.

## Comments: WHY only

A comment earns its place only when it states something the code cannot: a non-obvious WHY, an invariant, or a trap. If a comment restates WHAT the line does, delete the comment.

Keep (these are real WHY — do not strip):

- Architectural reasons a reader cannot infer: `// RLS-scoped to the participant`, `// polling is the fallback when the socket drops`.
- Invariants and gotchas that are easy to miss.
- JSDoc / TSDoc on public APIs — that is documentation, not narrative.
- Citing a durable contract for a rule: `// Per STRUCTURES.md §10C`, `// RULES.md #8`.
- Bare scope language: `// only honored in Phase 1`, `// Phase 1 fire-and-forget`.

The ban below targets dated/status/plan-tag narrative and AI residue — never authority citations or genuine WHY.

## Banned in source

### Machine-enforced (blocked by `pnpm lint:comments` + the comment-hygiene Stop hook (Claude Code) + the `comment-discipline` CI job)

These are detected on comment text of added/changed lines only (a ratchet — legacy is cleaned when next touched, not in one sweep):

- **Dates** in any form: `2026-07-13`, `13/07/2026`, `07-13-2026`, `Jul 2026`, `July 2026`.
- **Phase / plan tags**: `Phase 5.11`, `plan §22.10.L`, `§43`.
- **Status banners**: `Status: WIRED / DONE / DEFERRED / PENDING / BLOCKED / TODO`.
- **Plan / audit references**: `plan §…`, `audit §…`, `Notes.md`, `Plan.md`, `MAP PLAN`.
- **Ticket / audit codes**: `(B-1)`, `(H9-1)`.
- **AI self-attribution**: `added by Claude`, `generated by Codex`, `written by AI/Copilot/Cursor`, `as an AI`.
- **Request narration**: `as requested`, `per your request`, `as you asked`.
- **First-person change narration**: `I added…`, `we refactored…`, `I've updated…` in a comment.
- **Bare backlog markers**: a `TODO` / `FIXME` / `XXX` / `HACK` with no reason after it.

### Judgment (not regex-detectable — enforced by this skill + `kael-review`)

A senior reviewer would cut these even though a linter cannot:

- **Task / mission prose**: "this implements the booking flow Tu asked for", "part of the payment epic". Project-management WHY belongs in the PR, not the file. Technical WHY stays.
- **Restated code**: `// loop over users`, `// set count to 0`, `// return the result`.
- **Dead scaffolding**: commented-out code kept "just in case", empty placeholder blocks, `// add more here later`.
- **Editorializing / bias**: `// this is a hacky but clever trick`, `// obviously`, `// simply`, praise or apology.
- **Conversational tone**: comments addressed to the reader as if chatting. Comments are terse, technical, third-person or imperative — a margin note, not a voice.

## Diff & scaffolding hygiene

Output hygiene extends past comments — this is the writing-side complement of Core Skill 3 (Surgical Changes), not a duplicate of it:

- Do not annotate your own edit process (`// changed this line`, `// was 20, now 30`).
- Do not add comments to lines you did not otherwise touch.
- Do not leave debug logs; temporary probes are prefixed `[DEBUG-kael-...]` and removed before final (`critical.md` §24.14).
- A new file starts clean — no "scaffold" header describing what you intend to build in it.

## Before / after

Banned — a changelog and a self-report compiled into the file header:

```ts
// Phase 5.11 (plan §22.10.L, 2026-07-13): realtime subscription helper.
// Status: WIRED. Added by Claude as requested — I wired the polling fallback
// per the perceived-perf audit (kael-perf-audit §9) (B-1)(B-2).
```

Senior — WHY only; the rest goes to the commit message + docs:

```ts
// Realtime subscription helper for jobs, chat, and broadcasts.
// Target tables are RLS-scoped to the participant, so realtime honors the same
// access boundary as the REST reads. Returns null when Supabase is unconfigured;
// callers treat null as "stay on poll" (polling remains the fallback path).
```

## Self-check output

Before reporting a code change complete, confirm:

```text
Comments added: <count, or none>
Each earns its place (WHY/invariant/trap, not WHAT): yes/no
No AI residue (attribution, request narration, first-person, dates, status/plan/audit tags): yes/no
No dead code / bare TODO / restated-code / editorializing: yes/no
lint:comments on this change: clean / <violations>
```

## Enforcement

- `pnpm lint:comments` — full report (`scripts/check-comment-discipline.mjs`). `--diff <ref>` judges only lines added versus a ref (CI ratchet); `--working` judges only the current uncommitted change (Stop hook).
- The `comment-hygiene` Stop hook (`.claude/hooks/verify-comment-hygiene.mjs`) re-runs `--working` when code under `apps/`, `packages/`, or `supabase/functions/` changed, and blocks a false "done" on a new violation. It is wired in `.claude/settings.json`, so it fires for Claude Code only; Codex has no hook and runs `pnpm lint:comments --working` by hand.
- The `Comment discipline` step of the `controls` job in `.github/workflows/ci.yml` blocks banner comments anywhere in the repository, which covers the lines a PR adds.

All three are going-forward ratchets. Legacy files are cleaned when next touched, never in one mass rewrite.

| Rationalization | Reality |
|---|---|
| "Future me needs this history." | History lives in git + the commit message + `docs/`, not the source header. |
| "It documents the decision." | The decision goes in the commit message and docs; the comment states the one-line technical WHY. |
| "It is traceability to the plan." | Trace via the commit / PR, not phase tags compiled into the code. |
| "It shows what I did." | `git blame` and the diff show what you did. The comment is for the next reader, not a self-report. |
